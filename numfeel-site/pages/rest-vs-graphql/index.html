04 Conclusion: Why REST Still Remains Mainstream
GraphQL
  • Client-controlled precise fetching can reduce payload size
  • Nested data can be retrieved in one request
  • Trade-off: server-side cost can become unbounded
=
REST
  • Endpoints are contracts with predictable cost
  • GET is naturally cacheable and idempotent
  • Trade-off: extra fields can appear unless endpoints are designed carefully

GraphQL moves complexity from the client into the server. For a public API, the server pays for that flexibility. A common compromise is GraphQL inside a BFF and REST at the public boundary.

Data comes from the live Java backend numfeel-service: 200 authors, 10,000 books, and about 25,000 reviews. Open DevTools to verify response headers, payload size, and SQL-cost metadata.
